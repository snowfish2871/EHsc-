# EHsc · 纯 C++ 文件哈希与校验工具

**版本 2.1.1** · Windows 命令行工具 · **零第三方依赖**

```
============================================================================
  EHsc · 纯 C++ 文件哈希与校验工具   版本 2.1.1
  零第三方依赖：CRC32 / MD5 / SHA-1 / SHA-256 / SHA-384 / SHA-512 /
              SHA3-256 / SHA3-512 / BLAKE2s-256 / BLAKE2b-512
============================================================================
```

EHsc 是一个完全不依赖 OpenSSL、Crypto++、Boost、CNG(BCrypt) 等任何第三方或系统算法库的
哈希工具：**10 种哈希算法全部由本项目用标准 C++ 自行实现**。Windows 原生 API 仅用于
四件事 —— 文件选择对话框、控制台控制、文件读写、系统错误信息。

## 2. ⚠ 安全声明：MD5 / SHA-1 / CRC32 已经完全不适合安全计算

> **这一节请务必读完。它比本工具的任何功能都重要。**

EHsc 为了兼容旧系统与旧清单，仍然实现了 CRC32、MD5 与 SHA-1。但**这三者现在已经完全
不适合任何安全用途**。它们在本程序中的定位只有一个：**文件完整性检查**（检测偶发损坏、
比对副本是否一致）。**任何把它们当作"防篡改证据"的做法都是不安全的。**

### 2.1 一句话结论

| 算法 | 现在还能做什么 | 绝对不能做什么 |
| --- | --- | --- |
| **CRC32** | 检测复制/下载中的偶发位错误、ZIP 类格式的快速自检 | 任何安全用途（它不是密码学哈希，严格说连"哈希"都算不上） |
| **MD5** | 与老系统/老清单兼容读取、不担心敌手时的快速判重 | 防篡改、数字签名、口令存储、发布校验、证书、去重信任 |
| **SHA-1** | 兼容 Git 旧对象、旧清单、旧协议 | 防篡改、数字签名、证书、任何新设计 |
| **SHA-256 及以上** | 全部场景（含安全场景） | —— |

### 2.2 为什么它们不安全

**CRC32 —— 不是密码学哈希，只是线性校验和**

* CRC32 是 GF(2) 上的线性运算。攻击者修改任意数据后，可以**直接算出**需要同步修改哪几个
  字节来保持校验值不变 —— 甚至不需要"制造碰撞"这种概念。
* 它只有 32 位：即使不做任何恶意构造，随机两份不同文件也有 1/2³² 的概率误判相同；
  而在**恶意**场景下这不是概率问题，而是"想改就能改"。
* 结论：CRC32 只能用于**非对抗环境**下发现偶然损坏（网络传输、磁盘复制、压缩包自检）。

**MD5 —— 早已被彻底攻破（1996 年出现结构性缺陷，2004 年实用碰撞）**

* 2004 年王小云团队公布 MD5 碰撞攻击；此后**任意两个具有相同 MD5 的不同文件可以在普通
  电脑上以秒级时间构造出来**，而且前缀可以完全可控（chosen-prefix collision）。
* 现实后果：一份"和官网一致"的 MD5 清单**完全无法证明**你下载的文件就是官方文件 ——
  攻击者可以准备两个内容不同但 MD5 相同的文件，一个通过校验、一个真正执行。
* 已被实际用于恶意软件绕过哈希黑名单、伪造证书、伪造软件更新。
* **"加盐"或"再哈希一次（MD5(MD5(x))）"都不能挽救它。**

**SHA-1 —— 已被实际攻破（2017 年 SHAttered，此后成本持续下降）**

* 2017 年 Google 与 CWI 公布了**两份内容不同但 SHA-1 相同**的 PDF（SHAttered 攻击），
  一次性计算成本约 11 万美元等值的算力。
* 2020 年研究者把 chosen-prefix collision 成本降到约 4.5 万美元，此后仍在持续下降，
  **已经低于很多攻击者愿意为一个目标付出的成本**。
* 主流浏览器、证书颁发机构、Git（新对象）都已弃用 SHA-1。
* 结论：SHA-1 与 MD5 一样，**不能作为防篡改依据**。

### 2.3 使用建议（务必遵守）

**✅ 可以这样用**

```bat
:: 检测下载文件是否损坏（非对抗场景）
EHsc.exe hash D:\downloads\setup.iso -a crc32

:: 与老系统/老清单兼容：读取十年前遗留的 MD5 清单
EHsc.exe verify legacy.md5.txt

:: 快速判断两份副本内容是否一致（不涉及敌手）
EHsc.exe compare copyA.bin copyB.bin -a md5
```

**❌ 千万不要这样用**

* 用 MD5 / SHA-1 / CRC32 校验**从互联网下载的软件**，并据此认为"文件没被替换"；
* 把 MD5 / SHA-1 摘要写进发布说明、更新清单、供应链证明，作为**防篡改**依据；
* 用它们存储或比对**口令**（应该用 Argon2 / scrypt / bcrypt / PBKDF2）；
* 用它们做**数字签名**或证书（应该用 SHA-256/384/512）；
* 用 MD5/SHA-1 做"文件去重"并**信任**去重结果（攻击者可让两个不同文件同摘要）。

**🔁 应该改成什么**

| 场景 | 推荐算法 |
| --- | --- |
| 通用文件校验、软件发布、防篡改 | **SHA-256**（最通用）/ SHA-512 |
| 追求极致速度且需要安全性 | **BLAKE2b-512**（本工具中最快的安全算法之一） |
| 需要与 SHA-2 不同的结构（抗长度扩展等） | **SHA3-256 / SHA3-512**（Keccak 海绵结构） |
| 与新版工具链互操作 | SHA-256（事实标准） |

> **⚠ 特别提醒：同时列出多个弱算法并不会更安全。**
> 一份清单的可信度取决于**其中最弱的一环**。`-a all` 会同时算出包括 CRC32/MD5/SHA-1
> 在内的 10 种摘要 —— 这在**兼容性测试**中很有用，但请**不要**把这样的清单当作防篡改证据，
> 因为攻击者只需要攻破其中最弱的那一个。

### 2.4 本工具在程序内的提示

EHsc 会把上述立场贯彻到运行时：

* `EHsc.exe algos` —— 算法表带有 **"安全用途：✔ 可用 / ✘ 不适用"** 列，并在末尾打印完整的
  红色安全警告；
* 使用 `-a` 选中 CRC32/MD5/SHA-1 时，任务开始前会打印一条警告，说明它们只适合完整性检查；
* 生成的 **TXT / CSV 清单头部**会写入安全提示注释；**JSON** 会额外输出
  `"secure": false` 与 `"securityWarning"` 字段 —— 让清单的接收方也能看到这一限制。

## 3. 算法速查表

| 标识 | 名称 | 摘要长度 | 安全用途 | 说明 |
| --- | --- | --- | --- | --- |
| `crc32` | CRC32 | 4 字节 | ❌ **不适用** | ZIP/PKZIP 多项式 `0xEDB88320`；线性校验和，可任意伪造 |
| `md5` | MD5 | 16 字节 | ❌ **不适用** | RFC 1321；碰撞秒级可造，**已彻底攻破** |
| `sha1` | SHA-1 | 20 字节 | ❌ **不适用** | RFC 3174；已有实际碰撞（SHAttered 2017） |
| `sha256` | SHA-256 | 32 字节 | ✅ 可用 | FIPS 180-4；**通用首选** |
| `sha384` | SHA-384 | 48 字节 | ✅ 可用 | FIPS 180-4；SHA-512 内核截断 |
| `sha512` | SHA-512 | 64 字节 | ✅ 可用 | FIPS 180-4；64 位平台性能好 |
| `sha3-256` | SHA3-256 | 32 字节 | ✅ 可用 | FIPS 202；Keccak 海绵结构 |
| `sha3-512` | SHA3-512 | 64 字节 | ✅ 可用 | FIPS 202；Keccak 海绵结构 |
| `blake2s` | BLAKE2s-256 | 32 字节 | ✅ 可用 | RFC 7693；32 位平台优化 |
| `blake2b` | BLAKE2b-512 | 64 字节 | ✅ 可用 | RFC 7693；64 位平台优化，速度极快 |

命令行可用 `-a` 指定（大小写、`-`、`_` 均可忽略）：

```bat
-a sha256                 :: 单个
-a sha256,md5,crc32       :: 多个（逗号/分号/空格分隔）
-a SHA-256                :: 大小写与连字符不敏感
-a all                    :: 全部 10 种（含 3 个弱算法，仅建议用于兼容性测试）
```

## 4. 目录结构

```
EHsc/
├─ CMakeLists.txt            构建脚本（Visual Studio / Ninja 均可，静态 CRT 单文件输出）
├─ build.bat                 一键构建 + 打包 dist\EHsc.exe + 独立运行自检
├─ README.md                 本文档
├─ LICENSE                   MIT 许可证
├─ dist/                     构建产物：只需这一个 EHsc.exe 就能独立使用
├─ src/
│  ├─ hashes.h / hashes.cpp      10 种哈希算法纯 C++ 实现 + 内置测试向量 + 自检
│  ├─ win32_utils.h/.cpp         Windows 原生封装：文件对话框、控制台 UTF-8、
│  │                             目录枚举、CreateFileW 读写、隐藏属性、系统错误信息
│  ├─ core.h / core.cpp          引擎：作业控制（进度/暂停/取消/速度统计）、目录扫描、
│  │                             线程池调度、重叠 I/O 哈希、字节比较、基准测试
│  ├─ report.h / report.cpp      报告输出（TXT/CSV/JSON）、清单解析与校验
│  ├─ watch.h / watch.cpp        文件访问监听：系统句柄表采样 + 目录变更通知
│  ├─ ui.h / ui.cpp              控制台界面：彩色输出、实时进度面板、菜单、隐藏配置持久化
│  └─ main.cpp                   入口、命令行参数解析、各子命令实现
└─ tools/
   ├─ crosscheck_python.py       可选：用 Python hashlib/zlib 交叉验证全部功能（仅测试用）
   └─ mouse_test.cpp             可选：向控制台注入真实鼠标点击，验证点击操作（仅测试用）
```

设计原则：**相同功能集中在一个文件**，全项目只有 **7 个实现文件**，分为三层 ——
算法层（hashes）→ 引擎层（core / report / watch）→ 界面层（ui / main），中间由
win32_utils 提供平台能力。任何一层都可以单独复用。

## 5. 构建

### 前置要求

* Windows 10 / 11（或 Windows Server 2016+）
* Visual Studio 2019 16.11 及以上 / 2022 / 2026（需勾选「使用 C++ 的桌面开发」工作负载）
* CMake 3.16+（Visual Studio 自带一份，`build.bat` 会自动找到）

### 方式一：Visual Studio 直接打开（最省事）

1. 打开 Visual Studio；
2. `文件 → 打开 → 文件夹…`，选择 `EHsc` 目录；
3. VS 自动读取 `CMakeLists.txt` 完成配置（首次约 10 秒）；
4. `生成 → 全部生成`（`Ctrl+Shift+B`）；
5. 可执行文件位于输出目录（`out/build/x64-Release/` 或 `build/bin/`）。

### 方式二：命令行 CMake

```bat
:: 在「x64 Native Tools Command Prompt for VS」中执行
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
build\bin\EHsc.exe selftest
```

或使用 Visual Studio 生成器（多配置）：

```bat
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
build\bin\Release\EHsc.exe selftest
```

### 方式三：一键脚本

双击 `build.bat`：自动用 `vswhere` 定位 Visual Studio → 导入 `vcvars64.bat` →
优先用 Ninja 配置 → 构建 Release → 打包出 `dist\EHsc.exe` → **用 dist 里的 exe 跑一遍自检**，
确认脱离源码也能正常工作。


### 构建选项

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| `-DEHSC_CXX_STANDARD=17\|20` | `20` | C++ 标准；C++20 不可用时回退 17 |
| `-DCMAKE_MSVC_RUNTIME_LIBRARY=...` | `MultiThreaded`（`/MT`） | 改成 `MultiThreadedDLL`（`/MD`）即动态链接运行库 |

> 若你手工用 `cl.exe` 编译而漏掉了 `/utf-8`，`hashes.h` 中的 `static_assert` 会立即报错
> 提示，不会产生难以察觉的中文乱码。

## 5.1 独立分发（脱离源码使用）

EHsc 编译产物是**真正的绿色单文件程序**：

```
dist\
└─ EHsc.exe          ← 全部功能都在这个文件里，736 KB
```

* **只需要这一个文件**：拷到 U 盘、网络共享、任意目录都能直接运行；
* **不依赖源码**：exe 里已经包含了全部算法、界面、清单解析逻辑；
* **不依赖运行库**：使用静态 CRT（`/MT`）链接，实测依赖表只剩
  `KERNEL32.dll` / `SHELL32.dll` / `ole32.dll` / `ADVAPI32.dll` —— 这四个都是所有 Windows
  自带的系统库，**不需要安装 VC++ 可再发行组件包**；
* **不写注册表、不装服务、不改 PATH**：唯一可能产生的文件是程序同目录下的隐藏配置
  `ehsc.ini`（可删，删了会自动重建）；
* **可放在只读介质上**：配置写入失败时会自动改用 `%APPDATA%\EHsc\ehsc.ini`，功能不受影响。

验证方式（拷贝到一个空目录后执行）：

```bat
EHsc.exe selftest      :: 321 项算法自检
EHsc.exe hash C:\Windows\notepad.exe -a all
EHsc.exe algos         :: 算法与安全性说明
EHsc.exe config        :: 配置文件位置与状态
```

## 6. 命令行用法

### 6.1 命令总览

```
EHsc.exe                                   启动交互式菜单（推荐新用户）
EHsc.exe hash <文件|文件夹...> [选项]       计算哈希（可多目标、可递归）
EHsc.exe verify <清单文件> [选项]           校验清单（摘要/大小/缺失/读取错误）
EHsc.exe compare <文件A> <文件B> [选项]     字节级比较，定位首个差异
EHsc.exe bench <文件> [选项]                各算法吞吐量对比
EHsc.exe watch <文件|文件夹...> [选项]      监听谁读取/写入了这些文件
EHsc.exe selftest                           运行内置标准测试向量
EHsc.exe algos                              列出算法与安全性说明
EHsc.exe config                             显示配置文件位置与状态
EHsc.exe pick [--dir]                       调用 Windows 选择器并输出所选路径
EHsc.exe --help | --version                 帮助 / 版本
```

### 6.2 通用选项

| 选项 | 说明 |
| --- | --- |
| `-a, --algo <列表>` | 算法，如 `sha256,md5`、`all`（默认 `sha256`） |
| `-t, --threads <N>` | 线程数，`0` = 自动（CPU 核心数，最多 8） |
| `-b, --buffer <MB>` | 读取缓冲区大小，1–64（默认 4） |
| `-f, --format <fmt>` | 输出格式 `txt` \| `csv` \| `json`（默认取配置，初始 `txt`） |
| `-o, --output <文件>` | 结果写入文件（清单模式） |
| `--pick` / `--pick-dir` | 用 Windows 原生选择器补齐输入文件 / 文件夹 |
| `--filter <模式>` | 文件名通配过滤，如 `"*.exe;*.dll"`（分号分隔多模式） |
| `-r, --recursive` / `--no-recursive` | 递归子目录 / 仅当前目录（默认递归） |
| `--progress` / `--no-progress` | 强制 / 关闭进度显示 |
| `--ascii` | 使用 ASCII 进度条（`===` 而非 `███`），兼容旧终端 |
| `--quiet` | 只输出 `算法 摘要 路径` 三列，便于管道处理 |
| `--no-overlap` | 关闭读取/计算流水线（诊断用） |
| `--bom` | 输出文件带 UTF-8 BOM（Excel 打开 CSV 更友好） |
| `--no-colors` | 关闭彩色输出（ANSI 转义） |

`verify` 专用：

| 选项 | 说明 |
| --- | --- |
| `--base <目录>` | 清单中相对路径的基准目录（默认按清单记录的根目录解析） |
| `--no-checksize` | 不检查清单中记录的文件大小 |
| `--all` | 连校验通过的条目也一起打印 |

`compare` 专用：`--quick`（仅比大小）、`--no-hash`（不做摘要比对，只逐字节比较）。
`bench` 专用：`--seconds <N>`（每个算法的最短测试时长，默认 2 秒）。

### 6.7 `watch` —— 文件访问监听（谁读取/写入了它）

在指定的监听时间内，持续观察所选文件或文件夹，记录下**每一个打开过它的进程**及其
读写权限与持续时间，同时记录文件的变更时间线。

```bat
:: 监听一个配置文件 60 秒
EHsc.exe watch D:\app\config.ini --watch 60

:: 监听整个共享目录（递归），结果写成 JSON 报告
EHsc.exe watch D:\share -o D:\watch.json -f json --watch 300

:: 只看某个进程的访问
EHsc.exe watch D:\data --pid 4321 --watch 120

:: 不装驱动、不需要权限的纯变更时间线（看不到进程）
EHsc.exe watch D:\data --no-handles --watch 60
```

| 选项 | 说明 |
| --- | --- |
| `--watch <秒>` | 监听时长，`0` = 一直监听到按 `Q` / `Ctrl+C`（默认 30 秒） |
| `--pid <N>` | 只记录指定进程号的访问 |
| `--no-handles` | 关闭句柄采样，只保留目录变更通知（谁改的将无法得知） |
| `--no-notify` | 关闭目录变更通知，只保留"谁打开着文件" |
| `--include-self` | 连 EHsc 自身产生的事件也记录 |
| `--max-records <N>` | 最多保留的记录条数（默认 20000） |
| `--elevate` | 直接请求管理员权限（弹 UAC），不询问 |
| `--no-elevate` | 不提权、不询问，以当前权限监听（适合脚本/计划任务） |
| `-o` / `-f` | 把报告写成 txt / csv / json 文件 |
| `--filter`、`-r` / `--no-recursive` | 与其它子命令一致 |

#### 启动时的提权询问（管理员权限）

归因"是哪个进程"需要管理员权限 —— 只有提权后才能解析系统进程、服务与其他用户的句柄。
因此**未提权启动监听时会先问一句**：

```
⚠ 权限提示
  监听"是哪个进程读写了文件"需要管理员权限：只有提权后才能解析
  系统进程、服务与其他用户的句柄。不提权也能运行，但归因结果会不完整。
是否以管理员身份重新启动监听任务（会弹出 UAC 授权窗口）? (Y/N):
```

| 选择 | 行为 |
| --- | --- |
| **Y** | 走**正规 UAC 提权流程**：用 `ShellExecuteEx(runas)` 重新启动自己（参数原样带上），在**新窗口**中以管理员权限执行监听，窗口结束后停留等待回车；原窗口等它跑完再返回上一层 |
| **N** | 以当前权限继续监听，报告里会注明覆盖面限制 |
| **UAC 被拒绝** | **本次监听不执行**，提示"已取消管理员授权（UAC 被拒绝），本次监听未执行，返回上一层"，命令行退出码 `3`、菜单返回主菜单 |
| 提权启动失败 | 同样**不执行**，打印具体 Win32 错误；退出码 `4`。如确实不想提权请加 `--no-elevate` |
| **无人应答** | 提问**限时 30 秒**（可用环境变量 `EHSC_ELEVATE_TIMEOUT` 调整，`0` = 一直等），超时按"不提权"继续，避免脚本/计划任务被永久卡住 |

几点说明：

* 已经以管理员身份运行时**不会询问**（直接用当前权限）；
* 输入被重定向且缓冲区里没有内容时**不会询问**（避免脚本被卡住），此时按当前权限运行并提示
  "如需完整归因请加 `--elevate`"；`echo Y | EHsc.exe watch ...` 这种带输入的管道仍会正常询问；
* 提问本身也是**限时**的（默认 30 秒，可用环境变量 `EHSC_ELEVATE_TIMEOUT` 调整，`0` = 一直等）：
  在控制台前不动，超时后会打印"等待超时，按不提权处理"并以当前权限继续监听。
  自动化场景建议直接加 `--no-elevate`（不问不等）或 `--elevate`（不问、直接提权）；
* 提权必然要重启进程（Windows 不允许给已运行的进程提权），所以监听结果会显示在新窗口里 ——
  这是 UAC 的固有行为，不是本程序的取舍；
* 管理员窗口是**独立的控制台**（启动时带 `SEE_MASK_NO_CONSOLE`）。万一因为其它启动方式
  （计划任务、第三方启动器）导致标准句柄指向了不可用的控制台，程序启动时会自动检测并重新连接
  （此时打印一行 `[EHsc] 检测到标准流未连接到本进程的控制台…已自动重新连接`），
  所以输出与键盘始终可用 —— 不会出现"新窗口里一片空白、按 Q 也没反应"的情况；
* 正常重定向（`> log.txt`、管道）**不会**被误判：只有当句柄是"不可用的字符设备"、
  且本进程确实拥有控制台窗口时才会重连。

运行时的实时输出（每发现一个新进程就打印一行）：

```
── 文件访问监听 ────────────────────────
[2026-10-02 10:13:49]  读取      powershell.exe (pid 42188)  C:\data\secret.dat
[2026-10-02 10:13:51]  写入      powershell.exe (pid 31864)  C:\data\secret.dat
[2026-10-02 10:13:55]  内容写入  C:\data\secret.dat
```

结束后的报告（TXT 版）：

```
# === 进程访问（谁打开着目标文件）: 2 条 ===
[10:13:49.731 ~ 10:13:53.826]  读取        powershell.exe (pid 42188)   C:\data\secret.dat
[10:13:51.270 ~ 10:13:54.854]  写入        powershell.exe (pid 31864)   C:\data\secret.dat

# === 文件变更事件（Windows 不提供发起进程）: 1 条 ===
[2026-10-02 10:13:55.305]  内容写入  C:\data\secret.dat
```

**它是怎么做到的**（两条互补通道，都不需要安装驱动）：

| 通道 | 原理 | 能回答 | 局限 |
| --- | --- | --- | --- |
| **句柄采样**（默认开） | 周期性枚举系统句柄表（`NtQuerySystemInformation`），把目标文件上的句柄复制出来解析成"进程 + 访问权限 + 路径" | **是哪个程序**、以**读还是写**的方式打开、持续了多久、现在是否仍打开 | 采样间隔内打开又立刻关闭的访问可能漏掉；**非管理员**只能看到当前用户可访问的进程 |
| **目录变更通知**（默认开） | `ReadDirectoryChangesW` 实时监听目标目录 | 文件在**什么时刻**被新建/写入/删除/改名 | Windows 不提供变更发起者，进程一栏只能写"未知" |

两条通道互补：变更事件一到就立刻补一次句柄采样，因此"写完才关句柄"的程序也常常能被抓到。

> **想要最完整的覆盖面，请以管理员身份运行。** 非管理员时程序会在报告里明确写出这一限制
> （`note` 字段），绝不会假装自己看到了全部访问。

不带任何参数运行 `EHsc.exe` 即进入菜单，**所有操作都可以在界面内完成**：

```
  当前设置: 算法 SHA-256 | 线程 8(自动) | 缓冲 4 MB | 输出 txt | 进度条 开 | 流水线 开

── 主菜单 ──────────────────────────────
  1) 计算文件哈希          （可多选文件，Windows 原生选择器）
  2) 计算文件夹哈希        （递归 / 按通配符过滤）

  4) 校验清单文件          （检测篡改 / 缺失 / 大小变化）
  5) 字节级文件比较        （定位第一个不同字节）
  6) 算法速度对比          （同一数据下各算法吞吐量）
  7) 运行内置自检          （标准测试向量验证实现）
```

### 7.1 鼠标操作（Windows Console 鼠标支持）

在真实控制台窗口里运行时，**所有菜单都可以直接用鼠标点击**，键盘方式同时保留：

| 位置 | 点击效果 |
| --- | --- |
| 主菜单 / 设置菜单的任意条目 | 等同于输入该条目的编号（点击「9) 设置」直接进设置，再点「5) 进度条」直接切换并保存） |
| 进度面板的 `[空格]`、`[Q 或 Esc]` | 点 `[空格]` 暂停/继续，点 `[Q 或 Esc]` 取消当前任务 |
| 提权询问里的 `Y` / `N` | 选择是否以管理员身份重新启动监听 |
| 「按回车键返回主菜单…」提示行 | 任意位置点一下即可返回 |
| 其它区域（横幅、说明文字等） | 无反应，不会误触发 |

实现要点：

* 打开 `ENABLE_MOUSE_INPUT` 并关闭**快速编辑模式**（后者会吞掉鼠标事件，还会让点击变成
  "选择文本"从而阻塞输出）；退出程序时恢复原来的控制台模式；
* 点击位置来自 `MOUSE_EVENT_RECORD.dwMousePosition`（**控制台缓冲区坐标**，全角字符按 2 列计）；
* **按内容核对**：点击后程序会读出被点击那一行**实际显示的文字**，用条目关键字比对，
  而不是只信"登记时的行号" —— 这样即使输出把控制台缓冲区滚动上去、或条目后面的当前值
  刚刚变化过，也绝不会点错条目；
* 输入被重定向（管道 / 文件）时自动退回原来的键盘读行方式，脚本行为完全不变
  （`tools/crosscheck_python.py` 里的菜单用例就是走这条路径）。

> 说明：程序运行期间快速编辑模式是关闭的，因此此时**不能用鼠标选中文本复制**；
> 需要复制结果时请等程序退出（模式已恢复），或直接用 `-o` 把结果写成文件。

### 7.2 配置文件：隐藏的 `ehsc.ini`

首次运行（进入交互式菜单）时，程序会在**自己所在目录**生成配置文件，并**给它加上
Windows 隐藏属性**（`FILE_ATTRIBUTE_HIDDEN`），因此资源管理器默认看不到它，不会打扰普通用户。
文件是 UTF-8 纯文本，可以直接编辑：

```ini
# 被你找到了喵 (=^･ω･^=)          ← 第一行是留给好奇者的彩蛋，自己打开看看喵
# EHsc 配置文件（UTF-8）· 这个文件被设成了隐藏属性，删掉也不影响使用，程序会重新生成。
[general]
algos=sha256
threads=0
bufferMB=4
format=txt
progress=1
ascii=0
overlap=1
recursive=1
hidden=1
checksize=1
bom=0
colors=1
filters=
lastdir=
```

**写入位置按以下顺序自动选择**（写在哪个位置，后续就固定读它）：

| 顺序 | 位置 | 适用场景 |
| --- | --- | --- |
| 1 | `EHsc.exe` 同目录的 `ehsc.ini` | 绿色/便携使用（首选） |
| 2 | `%APPDATA%\EHsc\ehsc.ini` | exe 放在只读共享、光盘、无写权限目录时 |
| 3 | `%TEMP%\EHsc\ehsc.ini` | 兜底 |

**查看/编辑这个隐藏文件**（任选其一）：

```bat
EHsc.exe config                 :: 打印配置文件路径与状态
attrib -h ehsc.ini              :: 取消隐藏后即可在资源管理器中看到
notepad ehsc.ini                :: 直接编辑
:: 或在资源管理器「查看 → 显示 → 隐藏的项目」中勾选后查看
```

> 删除配置文件没有任何副作用：所有哈希功能都不依赖它，下次进入菜单会重新生成。
> 命令行子命令（`hash` / `verify` / `compare` / `bench` / `selftest`）**只读取**配置，不会创建或改写它。

## 8. 输出格式规范

### 8.1 文本清单（`-f txt`，兼容 `sha256sum` 校验习惯）

```
# EHsc 校验清单 v2.1.1
# 生成时间: 2024-05-01T04:33:20Z
#
# ⚠ 安全提示：本清单包含 CRC32, MD5。
#   CRC32 / MD5 / SHA-1 已经完全不适合任何安全用途：
#     · MD5 碰撞可在数秒内构造；SHA-1 已有实际碰撞攻击（SHAttered 2017）；
#     · CRC32 只是线性校验和，改数据时同步改校验值即可随意伪造；
#   它们仅可用于检测下载/复制过程的偶发损坏、比对副本是否一致，
#   绝不能作为防篡改、数字签名或发布验证的依据；安全场景请用 SHA-256 及以上。
#   注意：同时列出多个弱算法不会更安全 —— 可信度取决于最弱的一环。
#
# 根目录: D:\data
# 文件数: 1
# 算法: crc32,md5,sha256
# 格式: <摘要> *<相对路径>
# algorithm: crc32
90813dec *a.txt
# algorithm: md5
48601188008d1f63a69c2eb0dc960f4e *a.txt
# algorithm: sha256
bda9cd3f6d0d582e13b7ef6f37ffcb69564e358b36c7ed3ed3bfc20aebdcce47 *a.txt
```

* `#` 开头为注释；解析时忽略，但会识别 `# algorithm: xxx`、`# 根目录: xxx`。
* 摘要行格式：`<十六进制摘要> *<路径>`（`*` 表示二进制模式，与 sha256sum 一致）。
* 读取失败的文件列在末尾注释区（文本格式无法表达"无摘要的条目"）。

### 8.2 CSV 清单（`-f csv`，每行一个文件，每种算法一列）

```csv
# EHsc 校验清单 v2.1.1 生成于 2024-05-01T04:33:20Z
# ⚠ 安全提示: 本清单包含 CRC32, MD5，它们已完全不适合安全用途（易被伪造/碰撞），
#            仅可用于检测偶发损坏与副本一致性，不可作为防篡改依据；安全场景请使用 SHA-256 及以上。
# 根目录: D:\data
Path,Size,Modified,CRC32,MD5,SHA-256
a.txt,15,2024-05-01T04:31:15Z,90813dec,48601188008d1f63a69c2eb0dc960f4e,bda9cd3f6d0d58...
```

* 列名固定为 `Path,Size,Modified` + 每种算法一列（列名即显示名，如 `SHA-256`）。
* 若本次生成中有文件读取失败，会**追加 `Note` 列**写明原因，且该行摘要留空 ——
  校验时会被明确报告为"跳过（生成时读取失败）"，而不是被静默丢弃。
* 字段按 RFC 4180 转义（含 `,` `"` 换行时加引号，内部 `"` 双写）。
* 也支持读取"长表"格式：`Path,Size,Algorithm,Digest`（每行一个文件+算法组合）。

### 8.4 相对路径与基准目录解析规则

清单中的路径相对于**扫描根目录**，根目录同时写入清单（`roots` / `# 根目录:`）。
校验时基准目录的确定顺序：

1. 用户显式给出的 `--base <目录>`（**只按它解析，不回落**）；
2. 清单记录的根目录中**第一个真实存在**的目录；
3. 清单文件所在目录。

基准目录一旦确定就**严格解析**，不会"再去找一个同名文件"，因此清单可以随意移动位置，
而缺失的文件也一定会被报告为"缺失"。目标路径带尾部反斜杠（`EHsc.exe hash D:\data\`）
或以盘根为目标（`EHsc.exe hash C:\`）时，清单同样保留完整目录结构。

## 9. 退出码

| 码 | 含义 |
| --- | --- |
| `0` | 成功（哈希全部完成 / 校验全部通过 / 两文件相同 / 自检通过） |
| `1` | 结果异常（有文件哈希失败 / 校验发现不一致或缺失 / 两文件内容不同） |
| `2` | 清单或文件无法读取、清单解析失败、比较目标不是文件 |
| `3` | 用户取消（含：`watch` 提权时在 UAC 对话框上选择"否"，此时监听不执行） |
| `4` | 参数错误、没有可用目标、输出写入失败、提权启动失败 |

> 被取消而未处理完的文件计入「已取消」而不是「失败」，统计行单独列出，避免误导。

## 10. 实现要点

### 10.1 纯 C++ 算法实现细节

| 算法 | 实现要点 |
| --- | --- |
| **CRC32** | 256 项查表（首次调用时线程安全初始化），反射多项式 `0xEDB88320`，初值/终值取反，按大端输出 —— 与 zlib / PKZIP 一致 |
| **MD5** | RFC 1321 完整 64 轮，常量表 `floor(2³²·\|sin(i+1)\|)`，小端长度 |
| **SHA-1** | RFC 3174，80 轮，消息扩展循环左移 1 位，大端 |
| **SHA-256** | FIPS 180-4，64 轮，8 个 32 位状态字 |
| **SHA-384/512** | 共用 SHA-512 内核（80 轮、64 位字）；SHA-384 仅换初始向量并截断到 48 字节；128 位长度计数器形式完整 |
| **SHA3-256/512** | FIPS 202：Keccak-f[1600] 完整 24 轮（θ ρ π χ ι），海绵结构 rate = 200 − 2×输出长度（136 / 72），域分隔后缀 `0x06` + `pad10*1` |
| **BLAKE2s-256** | RFC 7693：10 轮、32 位字、σ 置换表完整、末块带 `last` 标志压缩、计数器按块长累加 |
| **BLAKE2b-512** | RFC 7693：12 轮、64 位字、128 位计数器 |

共同设计：

* 全部算法都是**流式状态机**（`update` 可被任意分块调用），与一次性计算结果完全一致；
* 状态结构全部是「平凡可复制」的 POD，统一放进联合体，`Hasher` **无虚函数、无堆分配**，
  可安全地每个线程各持一个实例；
* 填充逻辑严格按标准：MD5/SHA-1/SHA-256 用 56/64 边界，SHA-512 用 112/128，
  SHA-3 的 `0x06`/`0x80` 在 `pt == rate−1` 时正确合并为 `0x86`。

### 10.2 多线程与流水线

* **多文件**：`parallelFor` 线程池 + 原子下标分发；每个线程独立持有 `Hasher`，
  结果按下标写回各自槽位（每个元素只被一个线程写），无锁竞争。
* **单文件**：`OverlapReader`（1 个读取线程 + 4 块环形缓冲 FIFO 队列）把**磁盘读取**与
  **哈希计算**重叠起来。缓冲区较大时自动减少槽位，把每线程峰值内存限制在合理范围
  （4 MB→4 槽、16 MB→2 槽、>32 MB→退化为单缓冲顺序读取）。
* **进度统计**：`JobControl` 用原子计数器累计字节/文件数；瞬时速度用 **1.5 秒滑动窗口**，
  平均速度 = 累计字节 ÷ **有效运行时间**（暂停时长单独扣除，不污染速度与 ETA）。
* **ETA**：`剩余字节 ÷ 平均速度`，不足 1 秒或尚未开始计时时显示 `--:--`。

### 10.3 文件访问监听的实现（watch）

* **句柄采样**：`NtQuerySystemInformation(SystemExtendedHandleInformation)` 一次性取回全系统句柄表
  （约 17 万项、耗时约 15 ms），按 `ObjectTypeIndex` 过滤出 File 类型句柄。
  ⚠ 取类型索引必须解析 `OBJECT_TYPE_INFORMATION.TypeIndex`（x64 偏移 90）——
  该结构体第一个成员是 `UNICODE_STRING TypeName`，若误把开头两字节当索引，会把 Process 句柄
  当成 File 句柄（本项目的探针就踩过这个坑）。
* **取路径**：`DuplicateHandle` 复制句柄 → `GetFileType` 过滤掉管道/设备 → 先取卷内相对路径做预筛，
  必要时再用 `GetFinalPathNameByHandleW` 解析完整路径；设备路径经驱动器映射表还原成盘符路径。
* **判定读写**：按 `GrantedAccess` 位掩码分类 —— `FILE_READ_DATA|FILE_EXECUTE` 为读，
  `FILE_WRITE_DATA|FILE_APPEND_DATA|FILE_WRITE_EA` 为写，两者都有即读写，
  仅 `FILE_READ_ATTRIBUTES` 则记为"查询属性"（不含内容读取）。
* **句柄缓存**：以 (PID, 句柄值) 为键、内核对象指针做有效性校验，缓存路径与访问掩码；
  只有首次看到或句柄被复用时才做复制与解析，稳态下每轮开销极小。
* **两个线程组**：一个采样线程（默认 400 ms 一轮，收到变更事件立即插队补采），
  每个被监视目录一个通知线程（重叠 I/O + 取消事件，退出时 `CancelIo` 并 join）。
* **如实呈现**：报告里带 `note` 字段说明当前权限能看到什么，避免让使用者误以为"没有记录＝没有访问"。
### 10.4 鼠标点击的实现（Windows Console）

* 控制台输入一律用 `ReadConsoleInputW` 读取**输入记录**：键盘事件与鼠标事件从同一个队列来，
  因此键盘、鼠标可以共用一个 `pollConsoleEvent()`，不需要额外的窗口或消息循环（本项目没有 GUI）；
* 鼠标只取"左键按下"那一刻（记录上一次按键状态做边沿检测），忽略抬起、移动与滚轮；
* 可点击区域登记为"行 + 列范围 + 值 + 关键字"，其中：
  * 菜单条目登记整行，关键字取标题部分（第一个连续两个空格之前的内容），因此条目后面的
    "当前值"变了也照样能匹配；
  * 行内按钮（`[空格]`、`[Q 或 Esc]`、`Y`/`N`、格式选项）登记文字片段，
    列的换算用 `textDisplayWidth()`（全角按 2 列），与控制台报告的鼠标列坐标一致；
* 解析点击时**以屏幕文字为准**：用 `ReadConsoleOutputCharacterW` 读出被点击那一行的真实内容，
  再按关键字匹配；只有在读不到文字时才退回"行号匹配"。
  这样即使缓冲区滚动（长输出把菜单顶上去）、或面板每 100 ms 重绘一次，也不会点错；
* 点击区域用互斥量保护：进度面板在自己的线程里每帧重新登记，主线程解析点击，两者不会打架；
* 输入被重定向时不启用鼠标路径，菜单退回 `getline`，保证脚本/CI 行为不变。
### 10.5 中文与长路径

* 启动即 `SetConsoleOutputCP(CP_UTF8)` + `SetConsoleCP(CP_UTF8)`，并开启
  `ENABLE_VIRTUAL_TERMINAL_PROCESSING` 以支持颜色与光标控制；同时保留
  `ENABLE_PROCESSED_OUTPUT`，使 `\n` 在二进制模式下仍能正确换行；
* 命令行走 `GetCommandLineW` / `CommandLineToArgvW` 取宽字符参数，内部一律 `std::wstring`，
  只在输出时转 UTF-8；
* 超过 `MAX_PATH` 的路径自动加 `\\?\` 前缀，显示时再去掉；
* 进度面板按 **Unicode 显示宽度**（中日韩字符按 2 列）计算截断，避免中文路径折行破坏界面；
* 输入行会容忍意外的 UTF-8 BOM（管道/文件重定向常见）。

### 10.6 错误处理与资源释放

* 文件句柄、COM 接口、线程全部 RAII 封装（`WinFile`、`ComPtr`、`OverlapReader`），
  任何提前返回路径都不会泄漏；
* Windows 错误统一经 `FormatMessageW` 转为本地化文本并附 Win32 错误码；
* 单个文件失败**不会中断整批任务**，逐条记录并在结尾汇总；
* 取消后立即释放资源，**不产生半成品清单**；写盘时若 `WriteFile` 返回 0 字节
  （磁盘写满）会被判定为失败，不会误报"已写入"；
* 目录在扫描过程中消失、无权限访问等都会作为错误上报，不会被静默当成"空目录"。

| 5 | CRC32 ⚠ | 37.4 ms | 641.8 MB/s | 0.79× |
| 6 | SHA-1 ⚠ | 37.6 ms | 638.1 MB/s | 0.79× |
| 7 | BLAKE2s-256 ✅ | 43.8 ms | 547.6 MB/s | 0.67× |
| 8 | SHA-256 ✅ | 54.2 ms | 442.8 MB/s | 0.55× |
| 9 | SHA3-256 ✅ | 68.6 ms | 349.9 MB/s | 0.43× |
| 10 | SHA3-512 ✅ | 125.9 ms | 190.7 MB/s | 0.23× |

> **结论：BLAKE2b-512 只比 MD5 慢约 8%，却是安全算法** —— 在需要安全性的场景里
> 完全没有理由继续使用 MD5/SHA-1。速度差距从来不是使用弱算法的正当理由。
> 实际文件哈希时还会受磁盘 I/O 限制；启用流水线（默认）可让读取与计算重叠。

## 13. 常见问题

**Q1：为什么不直接用 Windows 自带的 CNG/BCrypt 算哈希？**
因为本项目的目标就是算法自行实现：它能保证在任何 Windows 版本上结果一致，
不受系统 FIPS 策略影响，也便于审计与移植。Windows API 只用于文件选择、控制台、
文件读写和错误信息这四件事。

**Q2：MD5 / SHA-1 / CRC32 既然不安全，为什么还要实现？**
为了**兼容**：大量旧清单、旧发布页面、旧脚本仍在使用它们，而且它们在
"检测偶发损坏"这一非对抗场景下依然有效（CRC32 尤其快）。请阅读第 2 节，
不要把它们用于任何安全目的。

**Q3：我同时算了 SHA-256 和 MD5，是不是更保险？**
不是。清单的可信度取决于**最弱的一环** —— 攻击者只需攻破 MD5 就能让篡改后的文件
通过校验。要么只用强算法，要么明确知道自己只是在做完整性检查。

**Q4：`watch` 说"未观察到任何进程打开目标文件"，是不是坏了？**
先确认是不是这两种情况：① 访问发生得比采样间隔还短（400 ms 内打开又关闭，比如
`findstr` 扫一遍就走）；② 访问者是系统进程或其他用户的进程，而你没有以管理员身份运行。
程序会在报告的 `note` 里如实写明当前权限能看到什么。想尽量多抓到，可以：
以管理员身份运行、用 `--no-handles` 至少拿到变更时间线、或把 `-a` 之类的长任务放在监听期间。

**Q5：为什么需要管理员权限才能看到所有进程？**
复制别的进程的句柄需要 `PROCESS_DUP_HANDLE` 权限，系统进程、服务、其他用户的进程默认
不授予普通用户。这不是本程序的限制，而是 Windows 的安全边界 —— 真要绕开就必须装内核驱动，
那既违背"单文件绿色程序"的目标，也有安全风险。

**Q6：`watch` 会不会拖慢系统？**
单轮扫描约 20 ms（约 17 万个句柄），默认 400 ms 采样一次；并且只有新出现的句柄才会做
"复制 + 解析路径"的开销（结果带缓存）。实测 CPU 占用可忽略。仍然建议只监听需要的目录。

**Q7：`watch` 启动时问我要不要提权，我该怎么选？**
想让报告里出现"哪个进程"，选 **Y**（会弹 UAC）。提权后程序会以管理员身份重新启动自己
（参数原样带过去），监听在新窗口里跑 —— 因为 Windows 不允许给已在运行的进程提权，重启是唯一
正规途径。选 **N** 也能监听，只是系统进程、服务、其他用户的访问不会出现在结果里，报告里会
注明这一点。**在 UAC 对话框上点"否"时，本次监听不会执行**，程序会退回上一层，不会偷偷用普通
权限跑一遍。

**Q8：为什么选 Y 之后结果在另一个窗口？**
同上：提权必须重启进程，新的管理员进程有自己的控制台窗口。该窗口会在监听结束后停留等待回车，
方便你看完成绩再关掉；原窗口会等它结束再返回菜单。脚本里不希望被打断时加 `--no-elevate`。
**Q9：管理员窗口里一片空白 / 按 Q 没反应，怎么办？**
2.1.1 已修复：管理员窗口现在使用**独立控制台**（`SEE_MASK_NO_CONSOLE`），不会再继承到
不可用的句柄。若在极特殊的环境下仍出现，程序启动时会打印一行
`[EHsc] 检测到标准流未连接到本进程的控制台…已自动重新连接`，随后输出与按键都应正常。
另一个常见"卡死"原因是 Windows 控制台的**快速编辑模式**：在窗口里点一下鼠标会进入选择状态并
阻塞输出；本程序运行期间会临时关闭该模式，退出时还原。若你的环境仍受影响，可在窗口属性里
取消勾选"快速编辑模式"。

**Q10：脚本里跑 `watch` 会不会被提问卡住？**
不会。提问有 30 秒上限（`EHSC_ELEVATE_TIMEOUT` 可调，`0` = 一直等），超时按"不提权"继续；
输入是没有数据的管道时则根本不提问。要完全跳过提问请加 `--no-elevate`（不问不等）
或 `--elevate`（不问、直接提权）。
**Q11：鼠标点了菜单但没反应？**
按顺序检查三点：① 是否在**真实控制台窗口**里运行（Windows Terminal / conhost 都行；
输出被重定向到文件或管道时鼠标不可用，程序会自动只用键盘）；② 是否点在了菜单条目上
（点横幅、说明文字等非菜单区域不会有反应，这是有意设计，避免误触）；
③ 该行是否已经被后续输出顶走 —— 程序会在点击时读取该行**实际显示的文字**再匹配，
所以即使缓冲区滚动也只会"点中你看得见的那一条"，不会误触发别的功能。
如果仍然异常，可以设置环境变量 `EHSC_DEBUG_CLICK=<日志文件路径>`，程序会把
"登记了哪些可点击行"和"点击落在哪一行、匹配到了什么"写进该文件，便于定位。

**Q12：为什么运行期间不能用鼠标选中文字复制？**
因为程序临时关闭了控制台的"快速编辑模式"：开着它时鼠标点击会被系统当成"选择文本"，
既不把鼠标事件交给程序，还会让后续输出阻塞（表现为程序卡死）。退出程序时会自动恢复原模式，
那时可以正常框选复制；需要保存结果时也可以直接用 `-o` 写文件。
**Q13：进度条显示成乱码方块？**
终端不支持 UTF-8 或虚拟终端序列时，使用 `--ascii` 切换为 ASCII 进度条。
重定向输出时默认不显示进度；如果确实想要，用 `--progress` 会输出每秒一行的纯文本进度。

**Q14：速度显示为什么有时是 0 或很小？**
小于几百毫秒的任务达不到速度采样窗口（1.5 秒滑动窗口），属于正常现象；
大文件会稳定显示瞬时与平均速度。

**Q15：`verify` 报"缺失"，但文件明明在？**
检查清单里的相对路径基准目录。EHsc 的解析顺序是 `--base` → 清单记录的根目录 →
清单所在目录，并且**严格解析**。如果清单是从别的机器生成的，用 `--base` 指到正确位置即可。

**Q16：能处理超过 4 GB 的文件吗？**
能。全程使用 64 位长度与偏移，实测 4.1 GB 文件与 Python 结果一致。

**Q17：能处理中文路径 / 网络路径 / 超长路径吗？**
能。内部一律宽字符，超过 `MAX_PATH` 自动加 `\\?\` 前缀；`\\server\share\...` 形式的
UNC 路径同样支持。

**Q18：`ehsc.ini` 在哪里？可以删除吗？**
默认在可执行文件同目录，并且带**隐藏属性**（所以资源管理器里默认看不到）。
用 `EHsc.exe config` 可以打印它的确切路径与状态；用 `attrib -h ehsc.ini` 取消隐藏后即可编辑。
如果 exe 所在目录不可写（只读共享 / 光盘 / 受控目录），程序会自动改用
`%APPDATA%\EHsc\ehsc.ini`，功能完全不受影响。删除它没有任何副作用，下次进菜单会自动重建。

**Q19：清单会被别人当作安全依据吗？**
本工具已在清单头部（TXT/CSV 注释、JSON 的 `secure` 与 `securityWarning` 字段）明确标注
弱算法警告。如果你要把清单交给他人，请使用 `-a sha256`（或更强的算法）生成。

**Q20：把 `EHsc.exe` 单独拷到别的电脑能直接用吗？需要装什么吗？**
不需要装任何东西。exe 采用静态运行库链接（`/MT`），依赖表里只剩 `KERNEL32.dll`、
`SHELL32.dll`、`ole32.dll` 这三个 Windows 自带库，**无需 VC++ 可再发行组件包、无需 .NET**。
换机器后建议先跑一次 `EHsc.exe selftest` 确认算法自检 321 项全通过。

**Q21：程序会在系统里留下什么？**
只可能在**自身目录**留一个隐藏的 `ehsc.ini`（写不进去就退到 `%APPDATA%`）。
不写注册表、不装服务、不建开机项、不改环境变量；清单文件只写到你用 `-o` 指定的位置。

**Q22：配置文件里第一行那是什么？**
那是留给愿意翻隐藏文件的人的彩蛋 —— 打开看看就知道了喵 (=^･ω･^=)。

## 14. 已知限制

* 仅支持 Windows（依赖 `IFileOpenDialog`、`CreateFileW`、控制台 API）；
* 单文件哈希的**计算**部分是单线程的（读取与计算重叠，但摘要计算本身不能并行，
  否则会破坏哈希链）；多文件之间是并行的；
* 目录扫描默认不跟随符号链接/联接点（避免循环），也不提供开关；
* 清单校验比对的是**摘要与大小**，不做逐字节比对（需要逐字节请用 `compare`）；
* `bench` 子命令只读取**单个文件**的前 64 MB 作为测试数据；
* **`watch` 的能力边界**（程序会在报告里如实写明，不夸大）：
  * 无法记录"某进程读取了文件的第 N 字节"这种块级细节 —— 句柄采样只能给出
    "谁、以读还是写的方式、从何时到何时打开着它"；
  * 比采样间隔更短的瞬时访问可能漏掉（变更事件一到会立刻补一次采样来缓解）；
  * 非管理员时无法归因系统进程、服务与其他用户的进程（Windows 的权限边界，不是 bug）；
  * 目录变更事件本身不含发起进程，这类事件只能记录时间与路径；
  * 需要**内核级**逐次 I/O 与调用栈追踪（Procmon 那种）必须安装文件系统微过滤驱动，
    与本项目"单文件绿色程序"的目标冲突，因此不做；
* **鼠标点击的适用范围**：仅在有真实控制台窗口时可用（Windows Terminal、conhost 均可）；
  输出或输入被重定向时自动退回键盘方式。程序运行期间会关闭控制台的"快速编辑模式"
  （否则鼠标事件会被系统吞掉、点击还会阻塞输出），因此这段时间内不能用鼠标选择文本复制，
  退出时会自动恢复原模式；
* 为换取"单文件免安装"，静态 CRT 会让 exe 体积比动态链接版大约 400 KB（736 KB vs 约 330 KB）——
  这是刻意的取舍。

**新增：`watch` 启动时的提权询问**

* 未以管理员身份运行 `watch` 时会**主动询问**是否以管理员身份重新启动，以取得最完整的归因结果；
* 选 **Y** → 用 `ShellExecuteEx(runas)` 走**正规 UAC 提权流程**重启自己（原有参数原样带过去，
  并追加 `--elevated-child`），监听在管理员窗口执行、结束后停留等待回车，原窗口等它跑完再返回上一层；
* **UAC 授权被拒绝时本次监听不执行**，打印"已取消管理员授权（UAC 被拒绝），本次监听未执行，
  返回上一层"并以退出码 `3` 返回；提权启动失败同样不执行（退出码 `4`）；
* 已提权时不再询问；输入被重定向且无待读数据时不询问（避免卡住脚本），
  可用 `--elevate` 强制提权、`--no-elevate` 完全不询问；
* 新增命令行参数 `--elevate` / `--no-elevate` / `--elevated-child`（内部用），
  以及调试用环境变量 `EHSC_ELEVATE_VERB`（覆盖提权动词）与 `EHSC_ELEVATE_SIMULATE`
  （`cancel` / `fail`：直接模拟 UAC 被拒绝或提权失败），便于自动化测试提权链路。

**修复：提权提问可能永久卡住调用方**

* 提问改为**限时询问**（`askYesNoTimed`，默认 30 秒）：在控制台里用键盘轮询实现，
  超时按"不提权"继续并打印"等待超时，按不提权处理"，脚本、计划任务、无人值守不再被永久阻塞；
* 超时秒数可用环境变量 `EHSC_ELEVATE_TIMEOUT` 调整（`0` = 一直等）；
* 新增判据：只有在"本来就是交互式控制台"时才提问 —— 若控制台是启动时重绑才拿到的
  （说明标准流原本被重定向），则不提问、直接以当前权限运行；
* 输入是没有数据的管道/文件时同样不提问，改为提示可用 `--elevate`。
**修复：UAC（管理员）窗口里无输出、按 Q 停不下来**

* 根因一：提权子进程此前会尝试继承父进程（中完整性级别）的控制台，拿到的是**不可用句柄**，
  于是 `std::cout` 写进了废句柄 → 新窗口一片空白。现在提权启动带
  `SEE_MASK_NO_CONSOLE`，子进程使用自己的独立控制台；
* 根因二：`stdoutIsTerminal()` 因此为 false → 进度面板没有启动（**键盘轮询在面板线程里**），
  而主循环的兜底条件用的是"配置项是否开启进度条"（默认开启）→ **没有任何线程在读键盘**，
  按 Q 自然无效。现在兜底条件改为"进度面板是否真的在运行"（`ProgressMonitor::isActive()`），
  面板没跑起来就由主循环接管按键；
* 防御性修复：新增 `rebindConsoleStreams()` —— 启动时若发现"本进程有控制台窗口，但标准流
  指向不可用的字符设备"，就重新打开 `CONOUT$` / `CONIN$` 并重绑 CRT 流（正常重定向不受影响）；
* `pollKey()` 改为直接用 `ReadConsoleInputW` 读取控制台输入记录（标准输入不可用时自动改用
  `CONIN$`），不再依赖 `<conio.h>` 的句柄缓存，提权后重绑控制台也能正常读到按键；

**本轮修复同时包含**

* 修复：管道输入中已被 C++ 流缓冲的数据不会被 `PeekNamedPipe` 看到，导致菜单流程跳过提权询问 ——
  改为"控制台 / 管道有待读数据 / 调用方确认为交互流程"三者取或。
* 修复：进度面板关闭时（`--no-progress` / `--quiet` / 重定向）"按 Q 停止监听"失效 ——
  改为由主循环自行轮询键盘；
* 修复：`--watch 0`（不限时长）在标准输入被重定向时无法用键盘停止，会留下停不掉的进程 ——
